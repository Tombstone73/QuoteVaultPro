# Post-M6 V2 source-reference audit

Baseline: `555414cbb96de65ef72b7556f78100a1b968ec91` on the reconciled `dev` worktree. Scope is V2 source only; V1 and historical migrations are unchanged.

## Evidence method

Parsed static imports, re-exports, import types, literal dynamic imports and `require` calls in 3,092 tracked JavaScript/TypeScript files. Relative `.js` references were resolved to TypeScript source, including directory indices and `@shared/` aliases. Runtime traversal used all three registered roots: `v2/src/main.ts`, `v2/src/deployment/entry.ts`, and `v2/ui/src/main.tsx`. Of 299 initial V2 production-source modules, 269 were reachable from those roots. The remaining 30 were individually checked against imports from tests/rehearsals/maintenance scripts and repository text references. Zero nonliteral dynamic imports or requires were found in V2. Static graph evidence was supplemented by route mounts, UI dispatch, deployment/build configuration, worker registration, and text searches for candidate filenames and exported symbols; graph unreachability alone did not authorize deletion.

`package.json` retains both `v2:build`/`v2:start` (foundation host) and `v2:server:build`/`v2:server:start` (deployed host). `v2/ui/index.html` and Vite use `ui/src/main.tsx`. That root dispatches `/portal` to `PortalApp`; all other routes use `AuthGate` and `App`. `App` and `productRouting.ts` implement the UI route dispatch; an absent React Router registration is not dead-code evidence. Deployment `server.ts` registers the QuickBooks billing, invoice email, and proof email workers and stops them during shutdown. The mounted HTTP routes are explicit in `src/interfaces/http/app.ts`; no filename-based module autoloading was found.

## Findings and disposition

### REMOVE NOW: approved and removed

Four source modules were deleted across the coordinated audit. The Builder/pricing owner removed `src/modules/pricing/parityFixtures.ts`, whose exports had no consumers, and preserved its historical characterization catalog in repository-root `docs/architecture/v2/M1_PRICING_PARITY.md`. The other three deletions are detailed below.

- `ui/src/InvoiceWorkspace.tsx` (35 lines): no imports, lazy imports, route registration or render references. `App.tsx` routes both invoice and payment pages to `FinanceWorkspace`. The one string-based consumer was a stale source-inspection test; it now checks the real Finance paged query/pagination and App route dispatch. No meaningful Finance behavior coverage was removed.
- `src/modules/artwork/quoteArtworkContracts.ts` (84 lines): zero module/string references. Its assignment/usage types duplicated the active `quoteArtworkApplication.ts` types used by Postgres and upload services. Its unused validator was weaker than the live validator, which enforces customer-supplied purpose and valid sides. The live service and acceptance SQL retain current quote evidence behavior.
- `src/repositories/contracts.ts` (26 lines): unconsumed generic scope/reader/writer skeleton. No importer or unique exported-symbol use exists. Current repositories use explicit domain transaction/read ports with organization predicates.

Two one-line uncalled pure closures were also removed after checking local symbol references: `identity` in Artwork application and `validPurpose` in Quote Artwork application. The active fingerprint and strict Quote usage validator remain. The historical Staff compatibility comments now identify their rehearsal-only purpose and current permission-set authority.

### KEEP

Twenty-six other modules outside runtime-root traversal have real rehearsal, recovery, or test callers. Keep physical-postcondition modules for all domains, clone safety, artwork storage reconciliation, formula freeze inventory/target tools, permission bootstrap/administration, delegated AI revalidation, and provider payment/refund reconciliation stores/services. Their absence from the production bundle is intentional and insufficient evidence for removal.

The M1.4 temporary Staff issuer, legacy membership map and Postgres membership reader remain executable in `runM14StaffAuthorityCompatibilityRehearsal.ts` and `staffAuthorityCompatibility.test.ts`. Current production issuance uses permission sets. Preserve this historical compatibility/rehearsal path pending an explicit retirement of those tests, not a linter finding.

Compatibility customer/product readers remain in current transaction paths. Mixed historical CRM, Quote/Order and financial data are supported and cannot be removed merely because new V2 writes use canonical contracts.
