# Settings Canonical Ownership Map

This document is the authoritative ownership map for settings after the legacy Admin Settings migration.

Rules:
- Every editable setting has exactly one canonical user-facing editor.
- Temporary API aliases are allowed only during migration.
- Temporary frontend aliases must redirect; they must not render editable duplicate controls.
- Platform-scoped settings must not share tenant/org settings editor surfaces.
- Operational dashboards must not become hidden settings editors.

| Setting / domain | Canonical frontend route | Canonical React component | Canonical API route | Canonical DB table / fields | Access scope | Legacy aliases / wrappers temporarily supported | Planned deprecation target |
| --- | --- | --- | --- | --- | --- | --- | --- |
